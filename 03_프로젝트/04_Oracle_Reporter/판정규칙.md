# Oracle 판정 규칙과 오프라인 범위

현재 구현은 합성 입력만 처리하는 `offline_mock` 프로토타입이다. 실제 A/B
모듈이나 랩의 관찰 출처를 인증하지 않으며 실제 취약점 성공을 증명하지 않는다.
공통 기준은 [PROJECT_SPEC.md](../00_공통/PROJECT_SPEC.md)다.

## 입력과 판정

`offline_oracle.decide(specialist, criterion, check=None)`는 원본을 수정하지
않고 ORACLE 봉투를 반환한다. 입력 오류는 `InputError`이며 제품 상태 FAIL이 아니다.

- specialist: v1 A/B 봉투. `target_id: SYNTHETIC-ONLY`, 모드 `offline_mock`만 허용한다.
  실행 행동이 있으면 UNKNOWN, 없으면 NOT_RUN이다.
- criterion: `criterion_id`, `target_id`, `selected_module`, 서로 다른 문자열
  `success_value`와 `failure_value`를 가진 함수 인자다. 공통 wire 필드 추가가 아니다.
- check: 테스트 호출자가 제공하는 별도 합성 관찰이다. A/B claim/evidence를
  그대로 최종 근거로 승격하지 않는다. 실행 ID·대상·모듈·기준·모드가 일치해야 한다.
  `source: synthetic-observer`, boolean `attempted`·`completed`,
  `execution_basis`와 `observed_value`, 선택적 `error`를 사용한다.

| 조건 | 최종 상태 |
|---|---|
| 실행·완료된 검사가 success_value와 일치하며 오류가 없음 | PASS |
| 실행·완료된 검사가 명시적 failure_value와 일치하며 오류가 없음 | FAIL |
| A/B 또는 Oracle 행동이 있으나 판정 근거가 부족하거나 상충함 | UNKNOWN |
| A/B와 Oracle 실행 행동이 모두 없음 | NOT_RUN |

값 없음·단순 마커 부재·도구 오류·성공 주장만으로 PASS/FAIL을 만들지 않는다.
실패 기준과의 명시적 일치가 FAIL 근거이며 단순 불일치는 UNKNOWN이다.
실제 A/B별 판정 기준은 해당 팀과 별도로 조율해야 한다.

PASS/FAIL에는 verify 행동과 같은 criterion_id의 verification 근거가 있다.
PASS는 matched, FAIL은 not_matched다. specialist_execution은 실제 합성 A/B
행동과 UNKNOWN을 요구한다. independent_check는 A/B NOT_RUN 뒤에도 허용되며
Oracle 자체 verify를 기록한다. 이 라벨만으로 현실의 독립 확인이 증명되지는 않는다.

## 저장 규칙

`offline_reporter.store([dispatcher, specialist, oracle], path)`는 네 번째
REPORTER 봉투를 만들어 새 JSON 파일에 저장한다. 원본 세 봉투와 Oracle
status/evidence를 유지한다. 기존 파일은 덮어쓰지 않는다. 상위 폴더는 호출자가
준비한다. 임시 폴더를 사용하는 기본 CLI는 종료 시 결과를 정리한다.

파일을 닫은 뒤 다시 읽고 complete-v1 및 원본 스냅샷과의 전체 동등성을
확인해야 반환 객체의 `storage`가 `written_and_verified`가 된다. 저장된 봉투의
`observation.storage: written`은 기록 라벨이며 재읽기 검증 성공은 함수 반환값으로
확인한다. 파일 내용만 보고 재읽기 성공을 추정하지 않는다.

오류 시 반환 객체의 storage는 failed이고 Reporter의 observation.storage도
failed이며 error.kind는 storage_error다. Oracle의 status/evidence는 유지한다.
오류로 일부 파일이 남을 수 있다. 원시 OS 오류나 경로를 반환하지 않으며 기존
파일을 보존하고 새 출력 파일로 재시도한다. 원자적 저장·재시작 복구는 미구현이다.

## 재현과 근거

[sample_io.json](sample_io.json)은 작은 fixture 인자와 기대 상태를 담는다.
`run_offline.inputs`가 완전한 Dispatcher/A/B 입력을 만들며, Oracle/Reporter는
그 입력으로 실제 합성 판정·저장·재읽기를 수행한다. 생성된 네 봉투는 임시 파일에만
있다. [QA.md](QA.md)는 실행 결과와 미실행 범위를 구분한다.
