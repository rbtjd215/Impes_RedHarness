# Oracle·Reporter 작업 규칙

루트 [AGENTS.md](../../AGENTS.md)와 [공통 협업 규칙](../00_공통/CODEX_개발협업.md)을 함께 따른다. 이 폴더는 최종 판정과 결과 보존의 개발 범위다.

## 시작

`Oracle 작업` 또는 `Reporter 작업`을 받으면 [공개 역할표](../00_공통/개발_역할표.md), [공통 계약](../00_공통/PROJECT_SPEC.md), [프로젝트 인덱스](../프로젝트_인덱스.md), [팀 안내](README.md), 최근 [Oracle 작업 기록](../91_개발작업기록/README.md)과 실제 Git 상태를 읽는다. 파트가 명확하므로 이름을 먼저 묻지 않는다. Oracle와 Reporter 중 개인 주 책임이 실제로 불명확할 때만 확인한다. 이름 확인은 안내용이며 접근 권한 검증이 아니다.

첫 답변은 **목표 / 지금 할 일 / 수정할 경로 / 테스트 방법** 네 항목으로 짧게 적는다.

## 단일 최종 판정

- 보통 `03_프로젝트/04_Oracle_Reporter/`와 자기 작업의 `03_프로젝트/91_개발작업기록/YYYY-MM-DD_oracle_<task-id>.md`만 수정한다. 다른 팀 파일·공통 계약 변경은 입력·출력·테스트 영향을 먼저 밝히고 담당 팀·팀장에게 PR 검토를 요청한다.
- Oracle만 [PROJECT_SPEC](../00_공통/PROJECT_SPEC.md)의 최종 `status`를 정한다. `PASS`는 외부에서 확인 가능한 성공 증거, `FAIL`은 실제 실행과 실패 근거, `UNKNOWN`은 실행했으나 판정 근거 부족, `NOT_RUN`은 실제 실행이 없음을 뜻한다. LLM 또는 A/B의 성공 주장은 외부 증거가 아니다.
- A/B가 분야별 근거 기준과 사례를 제안할 수 있지만 최종 판정은 Oracle 한 곳에서 한다. Reporter는 Oracle 봉투의 판정과 근거를 바꾸지 않고 저장한다. 저장 실패를 재판정으로 숨기지 않는다.
- 자동 요청은 허용된 자체 로컬 랩 정책을 따른다. 키·쿠키·개인정보·원시 민감 응답을 공개 로그에 넣지 않는다.

## 확인과 인계

공통 mock에서 네 상태, 성공 주장만 있는 경우, 근거 부족, 저장 실패를 검증한다. 실제 구현·랩이 없으면 각 검사를 `SKIP`과 이유로 적는다. 의미 있는 변경 뒤 [작업별 기록](../91_개발작업기록/README.md)을 갱신하고 짝의 판정 근거·로그 누락 검토를 PR에 남긴다. `작업 종료`·`인계`에는 실제 Git diff·HEAD·테스트로 handoff와 PR 설명을 작성한다. 앱 종료 뒤 자동 기록을 약속하지 않는다.
