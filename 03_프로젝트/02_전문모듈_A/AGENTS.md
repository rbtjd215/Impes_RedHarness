# A · 인증우회 작업 규칙

루트 [AGENTS.md](../../AGENTS.md)와 [공통 협업 규칙](../00_공통/CODEX_개발협업.md)을 함께 따른다. 이 폴더는 인증우회 모듈의 개발 범위다.

## 시작

`A파트 진행` 또는 `인증우회 작업`을 받으면 [공개 역할표](../00_공통/개발_역할표.md), [공통 계약](../00_공통/PROJECT_SPEC.md), [프로젝트 인덱스](../프로젝트_인덱스.md), [팀 안내](README.md), 최근 [A 작업 기록](../91_개발작업기록/README.md)과 실제 Git 상태를 읽는다. 지난 작업은 Git author·커밋·PR 이력과 대조하되 author는 신원·접근 권한 인증이 아니다. 파트가 명확하면 이름·짝·별도 작성자 정보를 묻지 않고, 담당 작업 범위가 실제로 불분명할 때만 범위를 확인한다.

첫 답변은 **목표 / 지금 할 일 / 수정할 경로 / 테스트 방법** 네 항목으로 짧게 적는다. 현재 할 일은 기록과 Git 상태를 대조해 정하고, 없는 구현·검증을 추측하지 않는다.

## 범위와 계약

- 보통 `03_프로젝트/02_전문모듈_A/`와 자기 작업의 `03_프로젝트/91_개발작업기록/YYYY-MM-DD_a_<task-id>.md`만 수정한다. 다른 팀 파일·Dispatcher 인터페이스에 영향이 있으면 먼저 입력·출력·테스트 영향을 밝히고 영향받는 팀과 조율해 PR에 남긴다. 공통 계약·최종 판정 책임·허용 범위 정책 변경은 동아리장의 명시 승인을 받는다.
- 두 구성원은 제공된 계획서·기존 프로토타입이 있다면 Codex와 검토해 도입·부분 도입·새 작성·보류 여부와 적용 방식을 스스로 정한다. 별도 검토·내부 승인 절차는 필수가 아니며 팀이 필요할 때 선택한다. 결정 근거와 실제 자체 검증 결과를 작업 기록·PR에 남긴다. 공개 가능 범위와 사용 권한을 확인하기 전 원본을 복사하지 않는다.
- A는 허용된 자체 로컬 문제의 인증우회 L1을 목표로 한다. 공통 v1 봉투에서 `selected_module: A`, `producer: A`와 필수 필드를 지킨다. 행동·관찰·증거 후보·오류·다음 행동을 반환한다.
- 중간 `status`는 실행 전 `NOT_RUN`, 실행 후 Oracle 판정 전 `UNKNOWN`이다. A가 분야별 근거 규칙을 제안할 수 있지만 최종 `PASS`/`FAIL`/`UNKNOWN`/`NOT_RUN`은 Oracle가 한 번 정한다. Reporter는 결과를 바꾸지 않는다.
- 자동 요청은 [PROJECT_SPEC](../00_공통/PROJECT_SPEC.md)에 등록된 고정 버전 자체 로컬 랩과 정해진 한도·초기화에서만 한다. 그 전에는 mock만 확인하고 실제 실행은 `SKIP`으로 기록한다.

## 확인과 인계

공통 mock 계약 검사, A 선택, A→Oracle 증거 전달을 확인한다. L1은 허용 랩의 실제 실행·외부 성공 증거·Reporter 로그까지 재현돼야 통과다. 실행하지 않은 검사는 `SKIP`과 이유로 기록한다. 의미 있는 변경 뒤 [작업별 기록](../91_개발작업기록/README.md)에 파일·시도·결과·테스트·막힘·다음 행동을 갱신한다. 별도 검토는 필수가 아니며 수행한 경우에만 그 결과를 PR에 남긴다.

`작업 종료`·`인계`에는 실제 Git diff·HEAD·테스트 결과를 확인해 handoff와 PR 설명을 만든다. 앱 종료 뒤 자동 기록된다고 약속하지 않는다. 공개 기록에 키·쿠키·개인정보·원시 응답을 넣지 않는다.
