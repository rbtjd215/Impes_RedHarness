# 환경 준비 기록 · <고유 작업 ID>

Codex가 실제 결과로 채운다. 파일명은 `YYYY-MM-DD_<team>_setup_<고유 작업 ID>.md`; team은 a, b, oracle, integration, common이다. 공유 세션 로그·출석·평가표가 아니며 이름을 파일명에 넣지 않는다.

- 날짜/체크포인트:
- 파트 / task-id / 작업 브랜치:
- 기준 SHA·fetch 확인 시점/결과·읽은 상대 경로:
- 원격 기준·남은 차이:
- 상태: 로컬 검사 <완료/미완료> / 기록 업로드 <확인/미확인> / PR <생성/미생성/실패 사유>:
- PR(생성 전이면 없음):
- 변경 추적: 이 파일을 포함한 Git author/committer·SHA·PR. 별도 이름·이메일 없음.

## 실제 준비와 검사

| 확인 방법·명령 | PASS/FAIL/SKIP | 실제 결과·기준 SHA/시점·건너뛴 이유 |
|---|---|---|
| 저장소 루트·예상 원격·현재 규칙/팀 안내·자기 인계 |  | 읽은 상대 경로·브랜치/PR/task-id 대응 |
| git --version / python --version |  | 최소 도구 버전 |
| 업로드 전 작성자 설정 본인 로컬 확인 |  | 확인 완료/확인 필요. 실제 이름·이메일 제외 |
| 자기 변경 보존·작업 브랜치·관련 없는 변경 분리 |  | 실제 상태 |
| 공통 두 fixture 검사 |  | 실제 명령·종료 코드·검사 수 |
| 계약 회귀 검사 |  | 실제 명령·종료 코드·테스트 수. 0개는 통과 아님 |
| 완성 mock 파이프라인 네 상태·임시 저장/재읽기 |  | 실제 명령·종료 코드·검사 범위. 실제 모듈/랩 아님 |
| 공개 diff·겹치는 작업 경로 확인 |  | 검토 상대 경로·확인/미확인 |
| 원격 브랜치 SHA·기록 반영 |  | 확인 시점/SHA 또는 미확인 이유 |
| PR 생성·head 확인 |  | 실제 URL·SHA 또는 미생성/실패 이유 |

로컬 검사 완료는 도구·루트/규칙·필수 검사 기준이다. 작성자 본인 확인·업로드·PR의 미완료는 별도 상태로 두고 로컬 검사 통과나 안전한 설계 읽기 검토를 막지 않는다.

## 시도와 아이디어

- 실제 변경 파일·시도·결과:
- 아이디어 상태(제안/선택/실험 채택/보류/폐기)·확인된 이유/미확인 사항(없으면 없음):
- 실제 모듈·랩 실행: 미실행. 이번 준비 검사와 구분.

## 인계

- 막힘·미확인 사실·자료 접근 실패 이유:
- 실제 Git과 기록의 차이:
- 다음 행동: 로컬 검사 통과 뒤 안전한 계획서/구현물 읽기 검토 가능. 기록 원격 확인 전에는 협업 업로드 완료로 표시하지 않음.
- 계획서/구현물: 제공 전 / 공개 안전한 상대 경로 / 검토 상태. 접근 불가면 이유·재첨부/경로 요청:
- 이어받을 브랜치·PR·task-id:

자기 최종 SHA를 넣기 위한 반복 commit은 하지 않는다. 마지막 업로드는 실제 원격 SHA·PR·완료 보고로 확인한다. 전체 대화·숨은 추론·개인정보·홈 경로·키·쿠키·원시 출력·개인 작업량 지표를 기록하지 않는다.
