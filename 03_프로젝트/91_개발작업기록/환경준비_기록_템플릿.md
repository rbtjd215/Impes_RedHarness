# 환경 준비 기록 · <고유 작업 ID>

Codex가 실제 결과로 채운다. 공유 세션 로그나 출석·평가표가 아니다. 파일명: `YYYY-MM-DD_<team>_setup_<고유 작업 ID>.md`. team은 a, b, oracle, integration, common 중 하나다.

- 날짜/체크포인트:
- 파트 / 작업 브랜치:
- 기준 커밋 / 확인 시점의 원격 상태:
- PR(생성 전이면 없음):
- 완료 범위: 로컬 확인 <완료/미완료> / 기록 업로드 <확인/미확인>
- 변경 추적: 이 파일을 포함한 Git 커밋·PR 이력 사용. 별도 이름·이메일을 쓰지 않음.

## 실제 준비와 검사

| 확인 방법·명령 | PASS/FAIL/SKIP | 실제 결과·건너뛴 이유 |
|---|---|---|
| 저장소 루트·예상 원격·팀 안내 읽기 |  | 읽은 저장소 상대 경로만 기록 |
| git --version / python --version |  | 최소 도구 버전만 기록 |
| 작성자 설정 본인 로컬 확인 |  | 확인 완료/확인 필요. 실제 이름·이메일 제외 |
| 기존 변경 보존·기준/작업 브랜치 확인 |  | 보존·분리 여부 |
| 공통 두 fixture 검사 |  | 실제 명령·종료 코드·검사 수 |
| 계약 회귀 테스트 |  | 실제 명령·종료 코드·테스트 수(0개는 통과 아님) |
| 기록 파일 공개 diff 검토 |  | 검토한 상대 경로 |
| 원격 브랜치 SHA·PR의 기록 확인 |  | 실제 확인 시점/커밋·PR 또는 미확인 이유 |

## 변경·시도·아이디어

- 실제 변경 파일·내용:
- 시도한 방법과 확인한 결과:
- 채택/보류/폐기한 방법·아이디어와 확인된 이유(없으면 없음):
- 모듈/실제 랩 실행: 미실행. 이번 준비 검사와 구분.

## 인계

- 막힌 점·미확인 사실:
- 실제 Git과 기록의 차이:
- 다음 행동: 필수 검사와 기록 원격 반영 확인 후 본인 계획서/구현물 요청. 이미 제공되었으면 해당 자료의 최소 도입 검토.
- 계획서/구현물: 제공 전 / 제공된 공개 안전한 상대 경로 / 검토 완료 중 실제 상태만 기재.

자기 최종 SHA를 파일에 넣기 위한 반복 커밋은 하지 않는다. 마지막 업로드는 실제 원격 SHA·PR 이력·완료 보고에서 확인한다. 전체 대화·숨은 추론·개인정보·홈 경로·키·쿠키·원시 실행 출력은 기록하지 않는다.
