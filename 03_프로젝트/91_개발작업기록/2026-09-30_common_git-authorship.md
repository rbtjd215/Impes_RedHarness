## 실제 변경

- 루트·공통·팀별 안내와 PR 양식에서 필수 짝 검토와 모든 모듈 PR의 팀장 승인·병합 절차를 제거했다.
- 팀 내부 구현·검토·계획서와 원본 도입 여부는 각 팀이 정하고, 공통 규칙 변경·예외만 동아리장 명시 승인을 받게 했다.
- 작업자 이름·짝 검토자 중복 입력을 제거하고 커밋 SHA·PR과 Git author/committer 이력으로 연결했다. 각자 clone과 자기 변경의 커밋, GitHub noreply 이메일 안내를 추가했다.
- 변경 대상은 개발 규칙·양식뿐이다. 코드, 원본 프로토타입, 과거 bootstrap 기록과 QA의 당시 사실은 수정하지 않았다.

## 확인과 인계

- Git 메타데이터: 작성자·커밋 생성자 필드와 변경 파일 조회 확인. 개인 설정값은 출력하거나 변경하지 않았다.
- Git 작성자 정보는 설정된 값이며 신원 인증이 아니다. 미커밋 변경이나 여러 사람의 작업을 한 명이 합쳐 만든 커밋에서는 실제 편집자를 추측하지 않는다.
- 문서 검증: PASS · Markdown 22개에서 상대 링크 86개가 모두 존재하고 `git diff --check`를 통과했다. 현재 규칙의 필수 짝 검토·매 PR 승인 절차가 제거되었으며 승인자는 동아리장으로 구분했다.
- 시작·인계 규칙 검토: PASS · A→`02_전문모듈_A/`, B/XSS→`03_전문모듈_B/`의 AGENTS·README와 공통 계약·최근 기록을 읽는다. 담당 미확인 때만 파트를 확인하고, 종료 후 재시작 때 기록과 HEAD·기준 커밋·PR·Git 상태를 대조한다. 실제 새 Codex 세션을 실행한 검사는 아니다.
- 코드 테스트: SKIP · 동작 코드와 fixture 변경 없음.
- 이전 종료 시 원격 인계: `codex/git-authorship` 브랜치만 업로드했다. 후속 병합과 원격 확인 결과는 PR #1 이력에 연결하며, 이 체크포인트 작성 시에는 아직 병합 전이다.
- 다음 작업자는 팀별 절차를 스스로 정하고 실제 테스트·막힘·다음 행동을 기록한다. 과거 기록에 남은 짝 검토 SKIP은 현재 작업의 미완료 조건이 아니다.
