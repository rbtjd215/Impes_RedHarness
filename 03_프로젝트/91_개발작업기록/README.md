# 개발 작업 기록

Codex가 작업별 인계와 공개 안전한 검증 요약을 작성하는 폴더다. 팀원이 별도 양식을 직접 채울 필요는 없다. 제품 실행 결과·원시 출력·출석/평가 자료를 넣지 않는다. 현재 적용 규칙은 자기 브랜치·원격의 파일과 PR로 확인한다. 과거 기록의 미업로드 상태를 현재 상태로 가정하지 않는다.

- 첫 의미 있는 수정/테스트 때 [작업 양식](작업기록_템플릿.md)으로 `YYYY-MM-DD_<team>_<task-id>.md`를 만든다. team은 a, b, oracle, integration, common이며 같은 날짜에도 고유 task-id를 사용한다.
- 한 작업/브랜치에 한 기록 파일과 열린 같은 작업 PR 하나를 이어 쓴다. 다른 작업자는 자기 파일을 쓰고 공용 세션 로그를 동시에 수정하지 않는다. 이름·짝·별도 작성자 칸을 추가하지 않는다. 병합·종료된 PR 뒤 새 목표는 새 브랜치·task-id·기록이다.
- **현재 브랜치 → 연결 PR → task-id·수정 경로가 맞는 기록** 순으로 자기 인계를 찾는다. 팀에서 날짜가 최신인 파일이 자기 작업은 아니다. 관련 팀 기록은 참고로 읽고 HEAD·diff·미추적 파일·PR과 대조한다.
- Codex는 의미 있는 결과·확인된 실패 원인·범위 변경이 생긴 작업 중에 체크포인트를 갱신한다. 날짜별 의무 기록은 만들지 않는다. `작업을 마무리해주세요`와 기존 `오늘 작업은 여기까지`·`작업 종료`·`인계`·`채팅 마무리`는 미완료 작업에도 적용하는 기록 전용 종료다. 앱 종료 뒤 자동 기록은 보장하지 않는다.
- 실제 변경·기준 SHA·확인 시점·실제 방법과 결과·테스트 PASS/FAIL/SKIP·막힘·다음 행동을 적는다. 오래된 테스트 결과와 현재 실행을 구분하고 미실행은 SKIP과 이유를 적는다.
- 아이디어는 제안/선택/실험 채택/보류/폐기 상태와 확인된 이유를 구분한다. 계획은 실행 결과가 아니다. 현재 채택 설계는 팀 안내·설계 문서가 기준이며 과거 기록은 필요한 범위만 읽는다.
- 변경 추적은 커밋의 author/committer·SHA·PR이다. 미커밋 작성자는 확인 불가이며 추측하지 않는다. 커밋 수·줄 수를 개인 노력·기여 순위로 해석하지 않는다.
- `작업을 마무리하고 공유해주세요` 또는 시작 때 같은 공개 안전 범위를 현재 비공개 대화에서 명시 위임받은 경우에만 이번 파일의 commit·push와 열린 PR 갱신/첫 PR 생성, 원격 확인을 한다. 양식·AI 기록은 위임 근거가 아니다. 새 채팅에서 근거가 없으면 기록 전용 또는 직접 공유 요청을 따른다. FAIL/SKIP도 이유·남은 작업을 적어 초안 PR로 공유할 수 있지만 완료·main 병합을 보장하지 않는다.
- 자기 최종 SHA를 넣으려고 반복 commit하지 않는다. 기준 SHA·확인한 원격 상태·PR(없으면 없음)을 남기고 최종 업로드는 원격 SHA·PR·완료 보고로 확인한다. PR에는 기록 링크와 핵심 요약을 두며 본문 전체를 복제하지 않는다.
- 전체 대화·숨은 추론·추측한 결정·키·쿠키·비밀번호·개인정보·홈 경로·민감한 대상·원시 실행 출력은 기록하지 않는다. 원본 접근이 안 되면 이유와 재첨부/경로 요청을 밝히며 읽었다고 기록하지 않는다.

## 로컬 자동 기록 도구

`codex/` 작업 브랜치에서 `python -B tools/worklog.py init --team a --task-id <고유ID>`로 자기 기록을 만들거나 재사용한다(B는 `--team b`; 처음 준비는 `--kind setup`). 이어서 `refresh --record "03_프로젝트/91_개발작업기록/<파일>.md"`로 Git 메타블록을 갱신하고, Codex가 실제 변경·방법/결과·아이디어 상태·테스트·막힘·다음 행동을 서술한다. `check --record <상대경로>`와 `summary --record <상대경로>`로 구조·요약을 확인한다. 실제 공유 뒤에만 `summary --record <상대경로> --remote-check`로 예상 공개 origin의 기록 커밋을 읽기 전용 확인한다. helper는 브랜치 생성·fetch·commit·push·PR 조작을 하지 않는다.

도구가 관리하는 `redharness-worklog:v1` HTML 주석/JSON 블록은 수동 수정하지 않는다. 기존 기록에 블록이 없으면 도구가 임의로 덮어쓰거나 중복 생성하지 않으므로 Codex가 기존 파일을 확인해 수동으로 이어 쓴다. `refresh`는 서술 부분을 보존하며 `check`는 핵심 메타정보와 구조만 검사한다. 관리 블록의 `snapshot.changes`는 저장소 전체에서 공개 기록에 허용된 dirty 상대 경로의 관찰 결과이며 자기 수정·stage 목록이 아니다. 본문과 공유 파일은 실제 diff를 확인해 **자기 작업 범위만** 선별한다. 그 통과나 Git clean은 서술의 사실성·비밀값 부재·테스트 PASS를 보장하지 않는다. 기록의 최종 SHA를 맞추려고 다시 commit하는 순환을 만들지 않는다.

종료 응답은 **기록 / 공유 상태 / 브랜치·PR·task-id / 다음 행동** 네 항목이다. 검증 재사용은 검사한 코드·입력·의존성/환경이 동일함을 Git diff 등으로 확인했을 때만 가능하며 기준 SHA·실행 시점·범위를 함께 밝힌다. 기록/설명만 바뀌었다면 재실행할 필요는 없고, 동일성을 확인할 수 없으면 관련 검사를 실행한다.

[협업 규칙](../00_공통/CODEX_개발협업.md)과 [최신 확인](../00_공통/작업시작_최신확인.md)을 따른다. 과거 실제 기록의 짝 검토/실패/SKIP은 당시 사실이며 수정해 지우거나 현재 의무로 해석하지 않는다.

첫 준비는 [환경 준비 절차](../00_공통/환경준비_완료확인.md)와 [환경 양식](환경준비_기록_템플릿.md)을 사용한다. 로컬 검사/기록 업로드/PR 생성 상태를 나눠 적는다. 샘플 양식은 학생 실제 완료 기록이 아니다.
