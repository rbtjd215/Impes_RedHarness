# 통합

Dispatcher → 선택된 A/B → Oracle → Reporter의 한 실행을 연결하는 담당 경로다. 아직 통합 실행 코드와 허용된 로컬 랩 정보가 없다. [PROJECT_SPEC](../00_공통/PROJECT_SPEC.md)의 공통 계약과 자동 실행 정책을 따른다.

기존 회장 배정으로 Dispatcher·전체 연결의 통합 범위를 조정한다. 통합 대행은 미확인이며 임의 지정하지 않는다. 각 팀의 도입 여부는 해당 팀이 정하고, 별도 내부 검토·승인을 둘지도 해당 팀이 선택한다. 팀장이 모든 모듈 PR을 필수 승인·병합한다는 뜻이 아니다. 통합 작업에서는 각 파트의 실제 테스트와 `SKIP`, 계약 영향과 전체 흐름의 호환성을 확인해 결과를 기록한다. 공통 계약·최종 판정 책임·허용 범위 정책 변경은 동아리장의 명시 승인을 받는다. 실행 결과를 공개할 때는 비밀값·쿠키·개인정보·원시 `runs/`를 제외한다.

[최신 확인](../00_공통/작업시작_최신확인.md)과 [공통 협업 규칙](../00_공통/CODEX_개발협업.md)을 따른다. 자기 브랜치·PR·task-id의 인계를 우선하고 관련 팀의 현재 설계·실제 검증·겹치는 경로를 대조한다. 일반 팀 PR을 회장이 모두 승인·병합하는 게이트는 없다. 통합에서 각 팀의 인터페이스·단일 Oracle 판정·Reporter 보존과 실제 랩 미검증을 구분한다. 동아리장 공통 예외 승인이 민감한 공개를 허용하지 않는다.
