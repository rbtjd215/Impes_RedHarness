# 공개용 개발 역할표

파트별 책임을 정의한다. 개인 이름·연락처·출결·평가 자료를 공개 저장소에 수집하지 않는다. 변경 추적은 각자 자기 변경의 Git author/committer·SHA·PR을 사용하며 신원 인증이 아니다.

| 파트 | 주 책임 | 목표·기본 경로 |
|---|---|---|
| A · 인증우회 · 2인 팀 | 분야별 행동·관찰·근거 후보 | 허용 로컬 문제 L1 · `03_프로젝트/02_전문모듈_A/` |
| B · XSS · 2인 팀 | 분야별 행동·관찰·근거 후보 | 같은 하네스 L0 · `03_프로젝트/03_전문모듈_B/` |
| Oracle·Reporter · 2인 한 팀 | Oracle 프로그램: 단일 최종 판정 / Reporter: 상태·근거 보존 | `03_프로젝트/04_Oracle_Reporter/` |
| Dispatcher·통합 · 회장 | 공통 연결·전체 실행 | `03_프로젝트/01_Dispatcher/`, `03_프로젝트/05_통합/`; 대행 미확인 |

팀은 목표 안에서 계획·분업·구현·내부 검토·프로토타입 채택·일반 PR 병합 담당/방법을 자율 결정한다. 짝 검토·동아리장 승인을 일반 PR의 의무로 추가하지 않는다. 다른 팀 영향은 당사자와 조율하고 공통 예외는 [협업 규칙의 표](CODEX_개발협업.md)를 따른다. 개인별 세부 분업·통합 대행을 추측하지 않는다.

Oracle 단일 판정은 프로그램 책임이며 팀원이 매 실행을 승인하는 절차가 아니다. 분야별 근거·mock·연결 예시는 A/B가 제안하고 팀 간 조율한다. 현재 B mock은 참고이며 채택·실제 L0 완료가 아니다. 실제 권한·병합 가능 여부는 GitHub 설정과 학생 계정에서 확인한다.
