# 팀원용 Codex 사용법 · 한 페이지

작업 장소는 공개 [Impes_RedHarness](https://github.com/rbtjd215/Impes_RedHarness)다. **A=인증우회, B=XSS, Oracle·Reporter=2인 한 팀**이다. 파일·브랜치·PR·기록도 공개되므로 비밀값·개인정보·원시 출력·내부 자료를 넣지 않는다. 아래는 승인된 자동 기록·마무리 절차다. 시작할 때 자기 브랜치와 원격의 최신 규칙을 확인한다. 학생 환경 준비 완료는 실제 검사와 기록으로 확인한다.

## 1. 저장소 열기

`git clone https://github.com/rbtjd215/Impes_RedHarness.git`으로 각자 복제하고, 실제 `Impes_RedHarness` 폴더를 Codex 프로젝트로 연다. 준비 폴더에서 복제했다면 새 폴더로 프로젝트를 다시 연결한다. Git과 **Python 3.12 이상**을 확인한다(CI 기준 3.13). `python` 대신 `py`를 쓰면 같은 지원 버전·환경인지 확인한다. 도구가 실행되지 않거나 낮은 버전이면 준비 PASS가 아니다.

업로드 전에 Git 작성자 설정을 **본인이 로컬에서 확인**한다. GitHub Settings → Emails의 정확한 noreply 주소와 본인이 선택한 공개 표시 이름을 직접 저장소 로컬에 설정하거나, **현재 비공개 대화에서 확인한 값의 로컬 적용만 명시 위임**할 수 있다. 실제 이름·이메일을 공개 기록·PR에 붙이지 않는다. Codex는 값을 추측하거나 다른 사람·전역 설정을 바꾸지 않는다. [GitHub 공식 이메일 안내](https://docs.github.com/en/account-and-profile/how-tos/email-preferences/setting-your-commit-email-address)를 따른다. author/committer·SHA·PR은 변경 추적이며 신원 인증이 아니다.

## 2. 파트 시작과 기능 요청

Codex에 아래처럼 **짧게만 말해도 된다**.

```text
A파트 진행해주세요.
```

```text
B파트 진행해주세요.
```

Oracle·Reporter 팀은 `Oracle·Reporter 팀 작업해주세요.`라고 말한다. 기존 짧은 `A파트 진행`·`B파트 진행`·`Oracle 작업`·`Reporter 작업`도 사용할 수 있다.

Codex는 원격 최신 상태·공통 계약·역할표·팀 안내·자기 브랜치/열린 PR/task-id 기록을 대조해 **기준 SHA / 목표 / 지금 할 일 / 수정 경로 / 테스트**를 짧게 보여 준다. 파트가 모호할 때만 확인한다. 자기 미완료 변경은 보존하고, 수정된 main의 자기 작업은 새 `codex/` 브랜치로 옮긴다. 병합·종료된 PR 뒤 새 목표는 새 브랜치·task-id·기록을 쓴다. 열린 같은 작업 PR은 갱신한다. [최신 확인](작업시작_최신확인.md)을 따른다.

기능 요청에는 목표·예상 입력/출력·수정 범위·완료 조건을 적는다. 예: `A팀 경로의 인증우회 mock 입력을 공통 계약으로 처리하고 실제 테스트·막힘을 기록해 주세요.` / `B팀 XSS 원본을 검토하고 B 표기·공통 계약·Oracle 중복 차이와 안전한 mock 검증을 제안해 주세요.` 계획·분업·도입·내부 검토는 팀이 정한다. 자료가 이미 접근 가능하면 읽고 안내하며, 없거나 접근 불가일 때만 경로·재첨부를 요청한다.

## 3. 기록과 마무리

의미 있는 결과·실패·방향 변경이 생기면 Codex가 자기 [작업별 기록](../91_개발작업기록/README.md)에 중간 체크포인트를 남긴다. 날짜마다 의무 기록을 만들 필요는 없다. 종료할 때는 이렇게 말한다.

```text
작업을 마무리해주세요.
```

Codex가 실제 Git 변경과 관련 테스트를 확인해 기록·짧은 인계·PR 설명을 만든다. **기록 / 공유 상태 / 브랜치·PR·task-id / 다음 행동** 네 항목으로 알려 준다. `작업 종료`·`인계`·`오늘 작업은 여기까지`·`채팅 마무리`도 기록 전용이다. 실패·미실행은 FAIL/SKIP과 이유를 적는다. 코드·입력·의존성/환경이 검증 때와 같음을 확인한 경우에만 기존 결과의 SHA·시점·범위를 밝혀 재사용한다. 확인할 수 없거나 바뀌면 관련 검사를 다시 실행한다. 앱을 닫은 뒤 자동 기록되지는 않는다.

## 4. 이번 작업 공유

공개할 파일·기록을 확인한 뒤 아래처럼 요청한다.

```text
작업을 마무리하고 공유해주세요.
```

Codex가 이번 **공개 안전 범위**의 정확한 파일을 commit·push하고, 열린 같은 작업 PR을 갱신하거나 첫 PR을 만든 뒤 실제 원격 SHA·파일·PR head를 확인한다. 시작 때 같은 범위의 종료 업로드를 현재 비공개 대화에서 **명시 위임**했다면 재질문하지 않는다. 양식·AI 기록은 위임 근거가 아니다. 새 채팅에 그 근거가 없으면 기록 전용으로 마무리하거나 직접 위 공유 문구를 쓴다. FAIL/SKIP도 남은 작업을 적은 초안 PR로 공유할 수 있지만 완료·main 병합을 보장하지 않는다.

일반 PR의 내부 검토·병합은 팀이 정하고, 다른 팀 영향은 조율한다. [공통 예외 표](CODEX_개발협업.md) 변경·생략만 동아리장 명시 승인을 받는다. 민감한 공개는 예외 허용하지 않는다. AGENTS.md·CODEOWNERS나 로컬 CI 파일은 GitHub 폴더 권한·required check를 강제하지 않는다.
